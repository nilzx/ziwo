## Verification

Ziwo's release gate passed 556 Worker tests, 172 Node tests, type checking,
installation of the packed package, upload/configuration comparison, bilingual
CLI dry runs and 317 prebuilt-Worker smoke tests. The connector's release gate
passed 170 tests with real isolated host modules on Node 24, with zero failures
and zero skips, plus package installation and an npm 11.15.0 publication dry run.
The lightweight Node 22 job is separate from that complete host release gate.

Each publication consumes the same tarball that its package job installed and
checked, after verifying its digest. PRs and manual workflows cannot publish.
Both tag workflows completed npm trusted publication with provenance and created
GitHub prereleases.

After publication, both registry downloads passed SHA-512 integrity verification
and matched their respective release CI tarballs byte for byte. Fresh isolated
installations on Node 26.13.1 passed Ziwo version/help/deployment dry-run checks
and connector import/build-material presence checks. Both `next` and `latest`
values were verified against the versions listed above; temporary installations
and caches were removed.

## Connector rc.1 publication failure

The connector's original `v0.3.0-rc.1` workflow failed before npm upload because
`dist/candidate.tgz` was interpreted as a GitHub shorthand rather than a local
file. The correction uses `./dist/candidate.tgz`, adds a real publication dry
run against that same file and explicitly passes the validated npm channel.
The failed tag remains at `02d0af34e72e9ce1c54026bc9827e30269bf93fb`; no connector
rc.1 package was uploaded by that run. The correction was published as rc.2,
without moving a tag or reusing a package version.

## Scope and recovery

This release does not update every deployment or migrate existing personal
data. The production instance was not changed. Ordinary MCP, enforced turn
refresh and a complete trusted host remain separate capability levels. The
optional reviewed dsh host preparation build is not stock dsh; complete dsh
0.2.2-rc.5 requires Node >=24.9.0.

Read the [installation, compatibility and recovery guide](../preview-release.md)
([简体中文](../preview-release.zh-CN.md)) before upgrading. Current memory backups
support v1–v4; v0.2.0 imports only v1. A memory backup excludes Directory authority
and host-side sessions/sidecars. A general in-place downgrade has not been
validated; production migration and real-subject continuity require separate
scoped evidence and approval.
