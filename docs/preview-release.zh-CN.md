# 0.3.0 预览版：安装、兼容与恢复

[English](preview-release.md)

候选版本为`@ziwo/memory@0.3.0-rc.1`和`@nilzx/dsh-mcp-connector@0.3.0-rc.1`。npm发布、测试服务器部署与主实例更新是不同动作；源码或本地测试通过不代表已经发布。预览版使用`next`，稳定版保留`latest`。

## 安装与更新

发布后，先用独立测试实例验证精确版本：

```sh
npx @ziwo/memory@0.3.0-rc.1 --version
npx @ziwo/memory@0.3.0-rc.1 deploy --dry-run --name ziwo-preview
npx @ziwo/memory@0.3.0-rc.1 deploy --name ziwo-preview
```

`@next`会跟随预览渠道，精确版本用于复现本次候选。预览CLI的帮助和后续命令固定当前版本，避免引导到旧稳定版。更新同一测试实例时保留Worker名称。npm包只分发预构建Worker和部署CLI；管理、评估、合规和Codex参考工具仍从仓库取得。GitHub部署按钮跟随所选源码分支，不跟随npm的`latest`。

## 支持范围

- Ziwo保留普通token/OAuth MCP和文本工具，新增稳定主体、人格评估/确认、初始化、增量同步、可信生命周期及可恢复的host登记。
- 连接器保留普通配置；`turn-sync`和`trusted-lifecycle`使用版本1能力要求，缺项或运行失败明确拒绝。配置成功不等于整体验收。
- 已验证dsh 0.2.2-rc.5的native执行器；完整等级需要单独构建、审查的构造前准入提案，stock dsh不自带。PTC不能用于强制刷新。
- Ziwo的Node最低版本由随包Wrangler声明；连接器声明Node>=20，完整dsh 0.2.2-rc.5声明Node>=24.9.0。此前Node22.23.5只验证可选构建及部分真实宿主模块，不代表完整dsh运行支持。
- 原生Codex CLI 0.171.0只完成普通MCP合成读写，不能据此承诺任意CLI/桌面会话的强制逐轮同步。

详情见[能力契约](mcp-client-contract-v1.md)、[客户端证据](mcp-client-validation.md)及连接器`docs/PREVIEW.md`。不能删除sidecar、重置归属或关闭门禁来绕过失败。

## 升级前与备份

真实数据更新前先核实实际版本、停止相关写入，为每个记忆体保存加密备份并在独立实例验证恢复；口令单独保管。同时记录Worker/账号、包版本、宿主/连接器版本、备份时间和范围。

部署不会自动给旧记忆分配主体。旧数据迁移需要独立批准、核实来源及预期实例；不能从名称猜测来源。普通读取不执行迁移，已有会话启用更强生命周期前也需处理可信归属。

旧数据备份为v1；带主体数据为v2；有已采用人格为v3；有初始化状态为v4。加密外层格式不变。当前代码支持导入v1–v4，v0.2.0只支持v1；不能删字段或改格式号伪造降级。

记忆备份不包含Directory中的host凭据、绑定、恢复授权，也不包含宿主会话和连接器sidecar。应一致保存宿主配置、会话和sidecar；Directory丢失属于另一类恢复，不能用新host证明旧会话没有绑定。恢复保留稳定主体但更换数据实例，每个受影响绑定都需显式重新关联，旧游标或同名路径不是授权。

## 回退边界

尚未证明新存储/备份格式可以原地安全降级到v0.2.0。回滚Worker代码不会撤销数据写入、人格采用或主体分配。

实际回退应停止写入，回到已验证的升级前备份/实例，并恢复匹配的包、宿主、配置、会话和sidecar，在隔离环境验证后再使用。备份之后的新写入不会自动合并，应保留后单独审阅；两个可写副本不能被当作已同步的会话。

R3测试服务器只演练可删除合成记忆的导出/恢复、主体不变、实例更新、损坏拒绝和精确清理；人格v3/v4与绑定恢复另有本地回归。它不是生产降级演练，也不解决Directory备份。

## 发布约束

两个仓库均校验包版本与精确`v<版本>`标签一致；PR及手动工作流只验证，即使手动选择标签也不发布。只有推送版本标签会发布：预览进入`next`并标记GitHub prerelease，稳定进入`latest`。发布作业使用验证过的同一压缩包和摘要，不重新构建。

发布前完成测试、真实包安装和测试实例验证；发布后查询registry并实际下载，和CI产物比对摘要，再安装下载包。`v0.2.0`和稳定dist-tag保持原样。

若npm已成功但GitHub Release失败，先核实版本、渠道和产物摘要，只补缺失的Release步骤；不盲目重发、不覆盖既有标签，也不复用版本号发布不同内容。
